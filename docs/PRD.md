# MetaVault PRD v0.8

## 1. 产品定位

**一句话：** 打通物理资产、数字资产、产品订阅的全生命周期管理工具。

**核心价值：**
- 数据打通：三类资产在同一系统，关联关系不丢失
- 智能提醒：到期、续费、保修、使用停滞，不再靠人记
- 优秀供应商管理：收藏优质供应商，采购时有据可查
- 二次消费（v0.6）：度量并促进资产的真实使用，让东西被"用起来"而非"囤起来"

**产品理念：二次消费**

一个东西被买下来或获得，是第一次消费；用自己的时间和精力去用它，是第二次消费。第一次消费只产生拥有感，只有尽可能多地二次消费，才能真正从东西中汲取能量。MetaVault 的职责因此从"管住资产"升级为"用起来资产"，落地为四个能力：

1. **记录** — 使用日志：每一次使用都记一笔（6.10）
2. **量化** — 单次使用成本：买价 ÷ 使用次数，暴露"买贵了却没用够"的资产（6.11）
3. **暴露** — 二次消费率 + 吃灰榜：仪表盘直接回答"我的东西用起来了吗"（6.12）
4. **行动** — 唤醒闭环：吃灰资产一键安排使用，勾选完成自动记使用（6.13）

**不是什么：** 不是记账App、不是ERP、不是密码管理器、不是打卡自律工具——使用记录完全靠用户主动，系统只负责让"用起来"可见、可量化、有出口。

## 2. 用户画像

**主要用户：** 个人知识工作者/数字游民
- 拥有物理设备（电脑、外设、家具等）
- 拥有数字资产（域名、课程、文件、软件许可、加密货币等）
- 订阅多个SaaS/会员服务
- 痛点：资产散落各处，关联关系丢失，到期靠人记

**演进路径：** 先自用验证 → 后期开放给同类用户

## 3. 资产模型

### 3.1 统一资产模型

所有资产共享基础字段，通过类型区分差异化属性：

| 基础字段 | 说明 |
|---------|------|
| id | 唯一标识 |
| name | 资产名称 |
| type | physical / digital / subscription |
| category | 细分类（如 physical.laptop, digital.course, subscription.saas） |
| status | active / idle / expired / disposed |
| tags | 自定义标签 |
| purchase_date | 获取日期 |
| purchase_price | 获取价格 |
| currency | 币种（默认CNY） |
| supplier_id | 关联供应商 |
| notes | 备注 |
| related_assets | 关联的其他资产ID列表 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

### 3.2 物理资产（type=physical）

| 扩展字段 | 说明 |
|---------|------|
| model | 规格型号 |
| quantity | 数量 |
| unit | 计量单位（个/台/套等） |
| location | 存放位置 |
| usage | 用途场景 |
| owner | 归属人 |
| source | 资产来源：purchase / self_build / donation / transfer |
| warranty_expiry | 保修到期日 |
| warranty_info | 保修信息（条款、联系方式） |
| depreciation_rate | 折旧率（年） |
| current_value | 当前估值 |
| serial_number | 序列号 |
| condition | 成色：new / good / fair / poor |

**细分类举例：** laptop, phone, tablet, monitor, furniture, camera, book, collectible, other

### 3.3 数字资产（type=digital）

| 扩展字段 | 说明 |
|---------|------|
| access_url | 访问地址 |
| expiry_date | 到期日（域名、证书等） |
| platform | 所属平台 |
| usage_stats | 使用情况（结构化，各子类型不同） |
| file_size | 文件大小（文件类） |
| file_format | 文件格式（文件类） |

**细分类举例：**
- **权益类：** domain, ssl_cert, crypto_wallet, software_license
- **内容类：** course, ebook, template, media
- **文件类：** document, design_file, code_repo
- **账号类：** account, api_key

**使用情况追踪（usage_stats）：**
- 课程：进度百分比、最后学习日期、总学习时长
- 文件：最后访问日期、访问次数
- 域名/证书：到期倒计时、DNS状态
- 账号：最后登录日期、活跃状态

### 3.4 产品订阅（type=subscription）

| 扩展字段 | 说明 |
|---------|------|
| billing_cycle | 计费周期：monthly / yearly / lifetime |
| next_billing_date | 下次扣费日 |
| amount | 每期费用 |
| auto_renew | 是否自动续费 |
| usage_frequency | 使用频率评估：daily / weekly / monthly / rarely |
| cancellation_url | 取消订阅链接 |
| trial_end | 试用到期日 |
| screenshots | 订阅截图（用于OCR识别到期时间） |

**细分类举例：** saas, membership, cloud_service, streaming, insurance, other

**截图追踪流程：**
1. 用户上传订阅页面截图
2. 系统通过OCR提取关键信息（服务名、到期时间、金额）
3. 用户确认/修正后保存
4. 后期目标：API对接各平台自动同步

### 3.5 使用日志（usage_events，三类资产通用，v0.6 新增）

一条记录 = 一次有意识的使用。由用户主动记录，系统不做自动猜测（不抓取、不定位、不推断）。

| 字段 | 说明 |
|------|------|
| id | 唯一标识 |
| asset_id | 关联资产（physical / digital / subscription 均可） |
| used_at | 使用日期，**统一为本地时区的 `YYYY-MM-DD` 日期字符串**（支持补录过去，不允许未来日期，见 3.5.1） |
| duration_minutes | 可选时长（1–1440 分钟） |
| note | 可选备注（这次用它做了什么） |
| source | 记录来源：quick（一键记今天）/ backfill（补录过去）/ checklist（清单勾选自动记，见 6.13） |

#### 3.5.1 日期口径（重要）

- `used_at` 只存日期不存时刻，按**服务器本地时区**解释（服务部署在用户本机，本地时区即用户时区），全链路格式统一为 `YYYY-MM-DD`，保证字符串比较即日期比较
- "今天" = 服务器本地日期；"不允许未来" = `used_at` 晚于本地今天时拒绝（400）
- 已处置（disposed）/已过期（expired）资产不再记录新使用（历史事件保留，仍参与单次使用成本回顾）

**什么算一次使用（按类型约定）：**
- 物理资产：实际拿出来用一次——写作、拍摄、试驾、穿着、开一次会等
- 数字资产：一次有产出的访问/学习——看一节课、用一次模板；点开就关不算
- 订阅：一次核心功能的真实使用——登录不算，用了才算

**与既有字段的关系：**
- 记录使用时同步刷新 digital 资产 `ext.usage_stats.last_access`，保证现有"使用停滞"提醒不受影响
- 订阅 `ext.usage_frequency` 手动评估保留，v0.6 后期升级为由使用日志统计驱动（见 6.5）
- 历史 `last_access` 不回填使用事件（历史不可考），从上线起记录

## 5. 关联关系

资产之间可以建立关联，表达真实世界的依赖和归属：

| 关联类型 | 说明 | 举例 |
|---------|------|------|
| depends_on | 依赖 | 域名 depends_on DNS服务 |

## 6. 核心功能

### 6.1 资产管理
- CRUD：创建、查看、编辑、归档/删除资产
- 列表视图：支持按类型、分类、状态、标签筛选和排序
- 详情视图：展示资产完整信息 + 关联资产 + 关联供应商
- 批量操作：批量修改状态、批量删除
- 通知页面：未读/全部筛选，批量已读/忽略

### 6.2 优秀供应商管理
- CRUD：创建、查看、编辑供应商
- 收藏：标记优质供应商，采购时优先参考
- 按供应商查看所有关联资产

### 6.3 关联管理
- 在资产详情页添加/移除关联
- 可视化关联图（MVP阶段可简化为列表）
- 删除资产时提示关联影响

### 6.4 提醒系统
| 提醒类型 | 触发条件 | 默认提前量 |
|---------|---------|-----------|
| 保修到期 | warranty_expiry 临近 | 30天 |
| 订阅续费 | next_billing_date 临近 | 7天 |
| 域名/证书到期 | expiry_date 临近 | 30天 |
| 试用到期 | trial_end 临近 | 3天 |
| 使用停滞 | 全部资产长期未使用（以使用事件为准，v0.6 起） | 最近活跃+30天，且到手满30天 |
| 折旧提醒 | current_value 低于阈值 | 低于原价10% |
| 取消建议 | 订阅使用频率低且即将续费 | rarely + 7天 |
| 替换建议 | 物理资产折旧严重 | 低于原价10% + 有收藏供应商 |
| 清单到期 | 检查清单 due_date 临近（仅进行中清单） | 3天 |

提醒方式：应用内通知 + Web Push 浏览器推送（已实现）。

> v0.6 已实现：「使用停滞」升级为基于使用日志、覆盖三类资产（最近活跃 = 最近事件 ?? digital 旧 last_access ?? purchase_date ?? created_at；到手满 30 天才判）；「取消建议」优先读使用日志（近 60 天 0 次且到手满 60 天 → rarely），从未记录事件且未满 60 天时回退手动 usage_frequency；停滞提醒 dismiss 后同一停滞窗口内不再重生。

### 6.5 采购建议
- 基于收藏供应商推荐：新增同类资产时，优先展示收藏供应商
- 续费决策辅助：订阅使用频率低时，提醒考虑取消；v0.6 起使用频率由使用日志自动统计（近 60 天 0 次使用且到手满 60 天 → 视为 rarely），手动评估仅作从未记录事件且未满 60 天时的回退
- 替换建议：物理资产折旧严重时，推荐同类收藏供应商

### 6.6 统计仪表盘
- 资产总览：按类型/分类的数量和金额分布
- 订阅费用：月度/年度订阅支出汇总
- 资产健康度：即将到期、使用停滞的资产数量
- 供应商分布：资产按供应商聚合

### 6.7 数据迁移
- **Excel导入：** 解析 .xlsx 文件，按列映射到资产字段，支持预览和字段匹配
- **CSV导入：** 通用CSV解析，自定义列映射
- **Obsidian导入（v0.7，v0.8 扩展）：** 上传 Obsidian Markdown 笔记（YAML frontmatter），解析为资产；frontmatter 带 id 时 upsert（存在则更新），无 id 则新建；供应商按名字精确匹配关联。v0.8 起正文中「## 使用记录」区块回读为使用事件（按 日期+时长+备注 去重合并，保留导入期间新产生的记录），其余正文仍不回读
- 导入流程：选择文件 → 预览数据 → 映射字段 → 确认导入 → 查看导入结果（Obsidian 分支：选择文件 → 预览 → 确认，无需映射）

### 6.8 数据导出
- **Excel导出：** 将资产或供应商数据导出为 .xlsx 文件
- **Obsidian导出（v0.7，v0.8 扩展）：** 将全部资产导出为 ZIP 包，每资产一个 Markdown 笔记（YAML frontmatter 扁平字段 + 正文含关联 wikilinks 与「## 使用记录」清单），可直接解压进 Obsidian Vault；与 Obsidian 导入构成**含二次消费数据**的完整备份闭环
- 资产导出：包含基础字段 + 类型扩展字段（扩展字段展开为独立列）+ 使用次数/最近使用（v0.8，仅报表用途，Excel 不承担备份）
- 供应商导出：全部字段（评分、标签、联系方式等）
- 导出流程：选择导出类型 → 点击导出 → 自动下载文件

### 6.9 场景化检查清单
- **场景模板：** 出差/旅行/日常检查/搬家/自定义，选择场景后基于模板 + 用户持有的资产自动生成清单项（如持有笔记本则自动加入并关联）
- **清单项管理：** 增删、重命名、勾选、上移/下移排序，条目可关联资产（资产删除时保留条目、置空关联）
- **进度与状态：** 勾选进度条、截止日期、整体标记完成（所有条目自动勾选）、归档/恢复
- **到期提醒：** 进行中清单的截止日期临近时生成"清单到期"提醒（并入 6.4 提醒系统）
- **仪表盘集成：** 进行中清单卡片（进度 + 跳转）

### 6.10 使用日志（v0.6 新增）
- **记录入口：** 资产详情页"记一次使用"——一键记今天（quick），或展开表单填日期/时长/备注
- **补录：** 支持添加过去日期的使用记录；支持批量补录——提交一个事件数组（单次上限 200 条，各条日期可不同），服务端整体在一个事务内写入，要么全成功要么全不写
- **历史列表：** 详情页按时间倒序展示使用记录，单条可删除（记错了）
- **三类通用：** physical / digital / subscription 均可记录；现有数字资产"标记已使用"按钮升级为本功能（旧 PATCH 接口放开三类并保留为兼容别名，行为详见技术设计 3.2.1）

### 6.11 单次使用成本 Cost Per Use（v0.6 新增）
- **公式：** `purchase_price ÷ 使用次数`（使用次数 = usage_events 计数）
- **适用范围：** 物理资产与数字资产；**订阅不参与**——订阅的支出是持续流出的租金而非一次性第一次消费，其使用效率由 6.12/6.5 的使用频率与取消建议覆盖
- **展示：** 资产详情页固定区块 + 资产列表可按此排序（从"最不划算"排起）
- **边界：** 无购买价 → 不展示；使用次数为 0 → 显示"从未二次消费"标记（而非无穷大），这是最重要的信号
- **口径：** 已处置/已过期资产仍参与计算（回顾这笔第一次消费的最终效率）；金额不做折现、不分摊，保持直觉简单

### 6.12a 月度回顾（v0.8 新增）
- 仪表盘卡片：本月二次消费 N 次 · M 件资产被使用 · 唤醒 K 件（首次使用落在本月的资产）
- 口径：含已处置/已过期资产的历史事件（回顾看全部发生过的消费行为，与 6.12 消费率的排除口径不同）
- 本月使用次数 Top 3 资产，点击跳详情

### 6.12 二次消费仪表盘（v0.6 新增）
- **二次消费率：** 过去 90 天有使用记录的资产数 ÷ 非 disposed/expired 资产总数（分子分母同口径，均排除 disposed/expired）
- **吃灰榜：** 最久未使用 Top 10（从未使用的按资产创建时间起算），展示类型色条 + 距上次使用天数
- **出口：** 吃灰条目提供"安排使用"入口（见 6.13），不制造愧疚感，直接给动作

### 6.13 唤醒闭环（v0.6 新增）
- **宿主清单识别：** 引入清单机器标记 `kind='wake_up'`（与用户自建清单彻底区分，不靠标题匹配）；宿主 = 最早创建的进行中唤醒清单，不存在则自动创建（标题"唤醒计划"，场景 custom）
- **入口：** 吃灰榜/资产详情页一键"安排使用"→ 追加一条关联该资产的清单项；同一唤醒清单内"未勾选且已关联同一资产"的条目已存在时不重复追加
- **闭环：** 勾选清单项视为完成一次使用，自动写入使用日志（source=checklist）
- **防重复计量：** 仅在未勾选 → 已勾选的跳变时记 1 条；取消勾选不回删事件；"整体标记完成"逐条按同一跳变判定（不走绕过逐项判定的批量 SQL）
- **作用域：** 仅 kind='wake_up' 清单的条目触发自动记使用；出差/旅行/搬家等场景清单勾选不记使用（带笔记本出门不等于"使用了笔记本"这次消费行为由用户自己判断后手动记）
- **复用：** 复用现有清单系统（勾选、进度、到期提醒、归档），不新建实体

## 7. 数据存储

**方案：** SQLite 文件数据库
- 单文件，易备份/迁移
- 无需额外服务
- 性能足够个人使用场景
- 后续多用户版本可迁移至 PostgreSQL

## 8. 技术方案

**架构：** Web 应用（Node.js 后端 + React 前端 + SQLite）

| 层 | 技术选型 | 理由 |
|---|---------|------|
| 后端 | Node.js + Express 5 + better-sqlite3 | 前后端同语言，同步 API 更简洁 |
| 前端 | React 19 + TypeScript + Vite | 生态成熟，组件库丰富 |
| UI组件 | shadcn/ui + Tailwind CSS v4 | 可定制、轻量，简约留白风格 |
| 数据获取 | React Query v5 | 自动缓存、后台刷新 |
| 路由 | React Router v7 | SPA 路由 |
| 数据库 | SQLite（服务端文件） | 单文件，易备份，零配置 |
| 包管理 | pnpm workspace monorepo | client/ + server/ 分包管理 |

**部署方式：** Express 同时提供前端静态文件 + API，单端口部署。

**数据目录：** SQLite 文件存放在 `./data/metavault.db`，WAL 模式启用。
